# ScrKeyboard v0.9.0 Input Coverage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an operator complete a business form using only the on-screen keyboard — punctuation, Polish diacritics and Tab navigation — and give the extension its own icons.

**Architecture:** The keyboard layout stays a pure function that turns a state object into rows of key descriptors; all new behaviour is expressed as new `KeyboardAction` variants that `keyboardView.ts` renders and `content.ts` dispatches. Two new pure modules (`diacritics.ts`, `fieldNavigation.ts`) hold the logic that can be tested without a browser. Icons are generated once from a single SVG and committed.

**Tech Stack:** TypeScript 7, Vite 8, Vitest 4, Chrome Manifest V3, no runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-08-17-v0.9-input-coverage-design.md`

## Global Constraints

- Node.js `>=22.0.0`; the extension targets `minimum_chrome_version: 116`.
- No new runtime dependencies. One new development dependency is allowed: `jsdom`.
- Code, comments and documentation use British English. The user-facing product name is `ScrKeyboard`.
- Do not rename these identifiers: `scrkeyboard.settings.v1`, `scrkeyboard.keyboardRuntimeState.v1`, `scrkeyboard-panel`, `scrkeyboard.syncContentScripts`, package name `scrkeyboard`.
- The persisted settings schema is not changed by this plan, so no migration is written.
- Keyboard copy lives in `src/content/keyboardCopy.ts`, never in `_locales/` — the keyboard follows the language stored in settings, not the Chrome UI language.
- `npm run check` (typecheck + tests + build + extension validation) must pass before every commit.
- Work happens on branch `feature/v0.9-input-coverage`.

```typescript
export const POLISH_DIACRITICS: Readonly<Record<string, string>> = {
  a: 'ą',
  c: 'ć',
  e: 'ę',
  l: 'ł',
  n: 'ń',
  o: 'ó',
  s: 'ś',
  x: 'ź',
  z: 'ż'
};

export function applyDiacritic(character: string): string {
  const lowerCase = character.toLowerCase();
  const variant = POLISH_DIACRITICS[lowerCase];

  if (!variant) {
    return character;
  }

  return character === lowerCase ? variant : variant.toUpperCase();
}
```

```typescript
function createCharacterRow(
```

```typescript
import { type EditableTarget, isEditableTarget } from './editableTarget';

const candidateSelector = 'input, textarea, [contenteditable]';

export function findNextEditableField(
  doc: Document,
  activeElement: Element,
  allowPasswordFields: boolean
): EditableTarget | null {
  const fields = Array.from(doc.querySelectorAll<HTMLElement>(candidateSelector)).filter(
    (element) => isNavigable(element, allowPasswordFields)
  );

  if (fields.length === 0) {
    return null;
  }

  const activeIndex = fields.indexOf(activeElement as HTMLElement);

  if (activeIndex === -1) {
    return fields[0] as EditableTarget;
  }

  const next = fields[activeIndex + 1];

  return next ? (next as EditableTarget) : null;
}

function isNavigable(element: HTMLElement, allowPasswordFields: boolean): boolean {
  if (!isEditableTarget(element, allowPasswordFields) && !isExplicitlyContentEditable(element)) {
    return false;
  }

  return isVisible(element);
}

function isExplicitlyContentEditable(element: HTMLElement): boolean {
  return element.getAttribute('contenteditable') === 'true';
}

function isVisible(element: HTMLElement): boolean {
  const view = element.ownerDocument.defaultView;
  let current: HTMLElement | null = element;

  while (current) {
    if (current.hasAttribute('hidden')) {
      return false;
    }

    const style = view?.getComputedStyle(current);

    if (style && (style.display === 'none' || style.visibility === 'hidden')) {
      return false;
    }

    current = current.parentElement;
  }

  return true;
}
```

`isVisible` walks the ancestor chain deliberately: jsdom does not inherit
`display: none` through `getComputedStyle`, and the walk also gives the correct
answer in Chrome.
