# ScrKeyboard v0.9.0 — Input Coverage Design

Date: 2026-08-17

Status: agreed, ready for implementation planning

Baseline: `0.8.2`

Parent: `2026-08-17-roadmap-to-store-design.md`

## Goal

An operator can complete a realistic business form using only the on-screen
keyboard: email addresses, dates, reference numbers and Polish names, moving
between fields without touching a physical keyboard. The extension also carries
its own icons.

## Non-Goals

- Fields inside nested frames or a page's own shadow roots. Tab navigation covers
  the top-level document only; frames are iteration 3.
- Honouring author-defined `tabindex` ordering. Document order is used instead.
- Remembering the symbol or diacritics mode between keyboard sessions.
- Any change to phrase buttons, site rules, or the options page.

## Layout

The keyboard keeps four rows plus the right-hand numeric keypad. A symbol column
is added to the keypad and is present in every mode.

### Letters mode

```
 q w e r t y u i o p          7 8 9  .
 a s d f g h j k l            4 5 6  ,
 ⇪ ⇧ z x c v b n m            1 2 3  -
 ?# ĄĘ Close [Space] ⇥ ↵      0  ⌫   @
```

### Symbols mode

Entered with `?#`, left with `ABC` in the same position.

```
 ! # $ % & * ( ) : ;          7 8 9  .
 " ' + = < > [ ] ?            4 5 6  ,
 ⇪ ⇧ ~ ^ | \ { } §            1 2 3  -
 ABC ĄĘ Close [Space] ⇥ ↵     0  ⌫   @
```

CapsLock and Shift keep their positions in symbols mode but are rendered as
disabled. Keeping the positions stable protects muscle memory; disabling them
signals that they do nothing here, which is clearer than a key that silently
ignores a press.

### Diacritics mode

Entered with the `ĄĘ` key. Only letters that have a Polish variant change; the
rest stay as they are.

```
 q w e r t y u i o p    →    q w ę r t y u i ó p
 a s d f g h j k l      →    ą ś d f g h j k ł
 z x c v b n m          →    ż ź ć v b ń m
```

Mapping: `a→ą`, `c→ć`, `e→ę`, `l→ł`, `n→ń`, `o→ó`, `s→ś`, `z→ż`, `x→ź`.

`ź` is placed on `x` because `x` does not occur in Polish words, so the position
is otherwise wasted.

Behaviour is one-shot, matching Shift: the mode clears after any `character`
action. Shift or CapsLock combined with diacritics produces the upper-case
variant (`Ą`, `Ć`, `Ę`).

### Keypad symbol column

`.` `,` `-` `@` occupy a fourth column beside the digits and are available in all
three modes, so the four most frequent characters in business form data never
cost an extra press.

## Modules

### New

- `src/content/diacritics.ts` — the base-to-variant map and a function that maps
  a character row, preserving case. Pure, no DOM.
- `src/content/fieldNavigation.ts` — collects candidate fields and selects the
  next one relative to the active element. Takes a document and an active
  element, returns an element or `null`.
- `icons/source.svg` plus generated `icons/icon-16.png`, `icon-32.png`,
  `icon-48.png`, `icon-128.png`.

### Changed

- `src/content/keyboardLayout.ts` — three new actions: `symbolLayer`,
  `diacritics`, `tab`. New symbol rows and the keypad symbol column.
  `createKeyboardRows` currently takes `shiftActive` and `capsLockActive` as
  positional flags and would grow to four; it is replaced by a single
  `KeyboardLayoutState` object. This is a refactor of code the change already
  opens, not unrelated cleanup.
- `src/content/keyboardView.ts` — renders the new keys and the disabled state.
- `src/content/keyboardController.ts` — dispatches the new actions; `tab` moves
  focus and leaves the panel open.
- `src/content/keyboardCopy.ts`, `_locales/en/messages.json`,
  `_locales/pl/messages.json` — accessible labels for symbols, letters,
  diacritics and Tab.
- `manifest.json` — `icons` and `action.default_icon`.
- `scripts/copy-extension-assets.mjs` — copies `icons/` into `dist/`.
- `scripts/validate-extension.mjs` — fails the build when a declared icon file is
  missing from `dist/`.

## Field Navigation Rules

- Candidates use the same predicate as `src/content/editableTarget.ts`, so Tab can
  never land on a field the keyboard refuses to serve.
- Order is document order.
- Skipped: `disabled`, `readonly`, and elements with no layout box.
- Password fields are skipped unless the matching whitelist rule allows them, in
  line with existing behaviour.
- No wrapping. On the last field, Tab does nothing and the panel stays open.

## Icons

`icons/source.svg` is the single source. Raster files are generated once with a
system tool (`rsvg-convert`, ImageMagick or Inkscape) and committed, with the
command recorded in the README. If no such tool is available in the working
environment, a small Node generator using the built-in `zlib` module produces the
PNGs from the same geometry.

Generation is deliberately not wired into `npm run build`: it would add a native
dependency to every build for an asset that changes about once a year.

## Testing

Tests are written before the implementation.

- `diacritics.test.ts` — complete mapping, letters without a variant unchanged,
  upper-case variants, idempotence when applied to an already mapped row.
- `keyboardLayout.test.ts` — symbol rows, keypad symbol column present in all
  three modes, CapsLock and Shift disabled in symbols mode, diacritics applied
  only to mapped letters.
- `fieldNavigation.test.ts` — document order, skipping disabled, readonly and
  hidden fields, password handling under both rule states, `null` at the last
  field.
- `validate-extension.mjs` — every icon declared in the manifest exists in
  `dist/`.

Manual verification uses `manual/webforms.html`: type an email address, a
reference containing a hyphen and a slash, and a name with diacritics, moving
between fields with Tab only.

## Risks

- **Row four grows from three keys to six** (`?#`, `ĄĘ`, Close, Space, Tab,
  Enter). If it becomes cramped on small screens, Close changes from a text label
  to a symbol, which frees the most width for the least loss.
- **Tab depends on page structure.** Forms that reorder fields with `tabindex`
  will feel wrong. Accepted for now; document order matches the visual order in
  ordinary forms, and the pilot will show whether it matters.
- **Mode discoverability.** An operator may not notice `?#` or `ĄĘ`. The pilot is
  the test; if it fails, iteration 2 adds a first-run hint.

## Acceptance Criteria

1. Every character needed for an email address, a slashed date and a hyphenated
   reference can be typed on an approved page.
2. All nine Polish diacritics are reachable in both cases.
3. A form of at least three text fields can be completed using only the on-screen
   keyboard, moving between fields with Tab.
4. Chrome shows the ScrKeyboard icon in the toolbar and on the extensions page.
5. `npm run check` passes.

## Version

`0.9.0` — new user-visible features, no breaking change to stored settings. The
settings schema is untouched, so no migration is required.
